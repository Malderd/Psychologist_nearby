# Quality Gate v1

**Проект:** Psychologist_nearby  
**Версия:** 1.0  
**Назначение:** контроль качества программных изменений перед их слиянием с основной веткой.

## 1. Критерии качества

| Критерий | Действие при проверке | Контур | Основание |
|---|---|---|---|
| Успешное восстановление зависимостей | Выполнить `dotnet restore` | Быстрый | Необходимость доступности зависимостей |
| Успешная сборка | Выполнить `dotnet build --no-restore -c Release` | Быстрый | Проверка компилируемости проекта |
| Статический анализ | Запустить анализаторы .NET | Быстрый | Обнаружение потенциальных ошибок |
| Критичное предупреждение CS0472 | Завершать сборку с ошибкой при наличии CS0472 | Быстрый | Предотвращение заведомо некорректных сравнений |
| Автоматические тесты | Выполнить `dotnet test` | Быстрый | Проверка работоспособности функциональности |
| Проверка конфигурации | Проверить реакцию приложения на отсутствие обязательного файла конфигурации | Расширенный | Проверка устойчивости запуска |
| Расширенный статический анализ | Запустить анализ с `AnalysisLevel=latest-all` и изучить дополнительные предупреждения | Расширенный | Выявление дополнительных проблем качества |
| Проверка покрытия тестами | Сформировать отчёт покрытия кода | Расширенный | Оценка полноты тестирования |
| Code Review | Проверить изменения и потенциальные граничные случаи | Расширенный | Предотвращение логических ошибок |

## 2. Правила прохождения Quality Gate

1. Сборка проекта должна завершаться без ошибок.
2. Критичное предупреждение CS0472 должно блокировать прохождение CI.
3. Автоматические тесты должны завершаться успешно.
4. Ошибки расширенного анализа должны быть рассмотрены разработчиком.
5. Изменения должны проходить проверку Code Review.

## 3. Реализация

Проверки сборки, статического анализа, тестирования, конфигурации и формирования отчёта покрытия реализованы в GitHub Actions в файле `.github/workflows/ci.yml`.

## 4. Ограничения

В версии Quality Gate v1 не установлены числовые пороги покрытия кода и автоматическая блокировка всех предупреждений статического анализатора. Расширенный анализ используется для дополнительного контроля качества.

**Автор документа:** разработчик проекта.
