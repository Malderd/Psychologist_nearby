\# ADR-002. Заменяемость логики интерпретации тестов



Автор: Паэгле Д. Д.

Статус: принято



\## 1. Контекст



В веб-приложении `Psychologist\_nearby` есть логика интерпретации результатов психологического теста (PHQ-9, GAD-7). Потребитель — `Testing.razor` — отображает вопросы и интерпретацию.



Изначально логика была статическим методом `TestScoreInterpreter.Interpret`, напрямую вызываемым из страницы. Это затрудняло тестирование и не позволяло подменить реализацию.



\## 2. Рассмотренные варианты



\*\*Вариант 1. Оставить статический метод.\*\*

\- Плюс: минимальные изменения.

\- Минус: невозможно подменить реализацию, тесты жёстко привязаны.



\*\*Вариант 2. Интерфейс + одна реализация.\*\*

\- Плюс: потребитель не зависит от конкретного класса.

\- Минус: нет второй реализации для доказательства подмены.



\*\*Вариант 3. Интерфейс + две реализации.\*\*

\- Плюс: полное покрытие P4, можно проверить подмену.

\- Минус: дополнительный файл, чуть больше кода.



\## 3. Решение



Использован интерфейс `IScoreInterpreter`, реализации `RangeScoreInterpreter` и `FixedScoreInterpreter`, а также DI через `builder.Services.AddScoped<IScoreInterpreter, RangeScoreInterpreter>()`. `TestScoreInterpreter.Interpret` оставлен как фасад для совместимости.



\## 4. Последствия



\- Потребитель не зависит от конкретной реализации.

\- Легко добавить новую стратегию интерпретации.

\- Потребитель теперь требует DI — нужен `IServiceProvider`.



\## 5. Способ проверки



\- `dotnet test` — все 46 тестов проходят.

\- Ручной запуск `/testing` — работает через `RangeScoreInterpreter`.
