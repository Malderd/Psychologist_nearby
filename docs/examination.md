# Протокол обследования Psychologist_nearby

| Поле | Содержание |
| --- | --- |
| **Дата и участники** | Беседа 1: 09.10.2026, очно, Паэгле Даниэла и заказчик — практикующий психолог (реальный заказчик). Беседа 2: 09.10.2026, по телефону (звонок), Куликов Константин и тот же заказчик. Участки: Паэгле Д. — тестирование, профиль пользователя, структура БД, интерфейс; Куликов К. — регистрация и вход, запись данных в БД, ядро приложения. |
| **Текущий процесс** | Клиент записывается через Instagram: пишет психологу, а она вручную вносит его в расписание. Контакты и результаты опросников хранятся в мессенджере. Номера телефонов теряются, имена клиентов забываются, возникают путаница со временем, двойные записи на одно время (приходится переносить) и потерянные заявки. Желаемый процесс по описанию заказчика: клиент регистрируется, проходит тест во вкладке «Тестирование», результат появляется в его кабинете и отправляется психологу в её кабинет. |
| **Подтверждённые потребности** | Принимать заявки в одном месте вместо Instagram и мессенджера. Обязательные данные клиента: имя и телефон (допустим Telegram). Тест нужен, чтобы подобрать формат работы: методика готовая, 25–30 вопросов с выбором ответа, оценка по баллам, подсчёт должна выполнять система. Результат видят клиент и психолог. Две роли: клиент и психолог. Расписание: ежедневно с 10:00 до 19:00, клиент выбирает время из свободных слотов, не более 4 записей в день, отмена не позднее чем за 1,5 часа; при конфликте на одно время одному из клиентов отказывают и предлагают альтернативу; занятия индивидуальные (не групповые). Статусы клиента: аккаунт создан → тест пройден → пробное занятие назначено → пробное прошло → остался или отказался; после пробного клиента спрашивают, продолжит ли он. В кабинете клиент видит статус записи и расписание, может изменить свои данные (например, удалить телефон или почту) и удалить аккаунт. Кабинет психолога: расписание на день; действия — назначить, перенести, отменить занятие, сменить личные данные. Дубли заявок удаляет психолог. Данные видит только психолог, в БД они хранятся в зашифрованном виде и хранятся постоянно. Напоминания о занятии нужны, с переносом в календарь. Неявка клиента последствий не имеет. Если клиенту нужен другой специалист, психолог направляет его сама, вне системы. Ожидаемая нагрузка: примерно 20 клиентов и 70 заявок. |
| **Примеры данных и ситуаций** | Синтетические данные. Полный тест: клиент `Тест Клиент`, телефон `+0 000 000-00-00`, ответы на все вопросы → баллы подсчитаны, формат работы определён, результат сохранён. Неполный тест: ответы не на все вопросы → итог не создаётся, клиент может продолжить. Двойная запись: два клиента выбирают один слот → вторая запись не создаётся, клиенту предлагается другое время. Лимит: пятая запись на один день → отказ с сообщением. Повторная регистрация: email уже есть в БД → аккаунт не создаётся, показано сообщение. Дубль заявки: две заявки с одним телефоном → психолог видит обе и удаляет лишнюю. Чужие данные: клиент Б запрашивает результат клиента А → отказ в доступе. |
| **Ограничения** | Команда из двух человек, срок ограничен семестром. Стек: C#, .NET 8, Blazor, ASP.NET Core Identity, Entity Framework Core; разработка в Visual Studio. Методика теста пока не передана заказчиком, поэтому подсчёт баллов нельзя реализовать до её получения. Данные о психологическом состоянии клиентов чувствительны: нужны разграничение доступа и шифрование. Вход с кодом из письма требует почтовой службы для отправки писем. Место размещения сайта пока неизвестно. Запасного способа записи при недоступности сайта нет. |
| **Предположения команды** | Незавершённый тест не считается итоговым результатом. Фраза «данные видит только психолог» означает, что результаты не видны посторонним и другим клиентам, а сам клиент видит свой результат. Вход по email, паролю (больше 6 символов) и шестизначному коду из письма, подтверждение почты только при входе и отсутствие восстановления пароля в первой версии описаны как реализация; их надо подтвердить как требования заказчика. Отмена позже чем за 1,5 часа не допускается (заказчик назвала только срок). Резервные копии в облачном хранилище с удалением предыдущей — план команды. Информация о специалисте на главной странице снижает барьер обращения; её состав с заказчиком не обсуждался. |
| **Открытые вопросы** | Название методики, шкалы, ключ подсчёта, пороги отнесения к формату работы и сами форматы работы (Паэгле Д.). Допустимый формат телефона (Паэгле Д.). Сохранять ли прогресс незавершённого теста (Паэгле Д.). Нужна ли статистика по клиентам: Паэгле Д. записала её как приоритет, Куликов К. получил ответ «нет» (общий вопрос, уточнить у заказчика). Длительность занятия и слота (Куликов К.). Период для «20 клиентов и 70 заявок» — в месяц или иной (Куликов К.). Как создаётся аккаунт психолога (Куликов К.). Срок действия кода входа и сервис отправки писем (Куликов К.). Какой календарь используется для переноса записи (Куликов К.). Согласие клиента на обработку персональных данных: заказчик считает его ненужным, оценить риск (команда). Выбор СУБД: README указывает MySQL, код использует SQL Server (LocalDB) (команда). Место размещения (команда). Срок уточнения: до фиксации baseline MVP. |
| **Решения** | Для ближайшей версии выбраны: две роли (клиент, психолог); регистрация по email и паролю с повтором пароля, запрет повторной регистрации на один email; вход с кодом из письма (после подтверждения у заказчика); заявка и профиль с обязательными полями «имя» и «телефон»; тест с автоматическим подсчётом баллов и определением формата работы; показ результата клиенту и психологу; расписание 10:00–19:00 с выбором свободного слота, лимит 4 записи в день, отказ с предложением альтернативы при конфликте; статусы клиента по цепочке из обследования; кабинет клиента (статус записи, расписание, правка данных, удаление аккаунта); кабинет психолога (расписание на день, назначить, перенести, отменить занятие, удалить дубль); разграничение доступа клиент / психолог; шифрование телефона и результатов теста в БД. В резерв предложены: восстановление пароля по коду из письма, перенос записи в календарь и напоминания, статистика по клиентам и выгрузка данных (требуют согласия заказчика). Вне системы: направление клиента к другому специалисту. |
