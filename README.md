# Psychologist_nearby («Психолог рядом»)

Веб-приложение для практикующего психолога. Клиент регистрируется, проходит тест, получает рекомендуемый формат работы и записывается на пробное занятие в свободное время. Психолог видит заявки, результаты тестов и расписание в одном месте вместо Instagram и мессенджера, где сейчас теряются номера телефонов и возникают двойные записи.

Проект учебный, заказчик — реальный психолог. Приложение разрабатывается на **C#**, **.NET 8** и **Blazor**.

## Как это работает

```text
Регистрация → вход с кодом из письма → профиль (имя, телефон) → тест
→ автоматический подсчёт баллов и формат работы → результат у клиента и у психолога
→ выбор свободного слота и запись на пробное занятие
→ пробное занятие → решение клиента: остался или отказался
```

Подробнее: [`docs/mvp.md`](docs/mvp.md) и [`docs/requirements.md`](docs/requirements.md).

## Что входит в MVP

- регистрация и вход, две роли: клиент и психолог;
- профиль клиента (имя и телефон), изменение данных и удаление аккаунта;
- тест (25–30 вопросов с выбором ответа) с автоматическим подсчётом баллов;
- показ результата клиенту и психологу;
- запись на пробное занятие из свободных слотов (ежедневно 10:00–19:00), защита от двойной записи, не более 4 записей в день, отмена не позднее чем за 1,5 часа;
- кабинет клиента (статус записи и расписание) и кабинет психолога (расписание на день, заявки, результаты, удаление дублей);
- шифрование телефона и результатов теста в базе данных.

Резерв: восстановление пароля, напоминания и перенос в календарь, статистика по клиентам, уведомления в Telegram.

- **C#** и **.NET 8**;

## Запуск

Требуется: **.NET 8 SDK**, **Visual Studio 2022** или другая среда разработки, доступ к базе данных проекта.

```bash
git clone https://github.com/Malderd/Psychologist_nearby.git
cd Psychologist_nearby
dotnet restore
dotnet run --project Psychologist_nearby
```

Перед запуском нужно настроить подключение к базе данных. Секреты (строка подключения к рабочей базе, ключ шифрования, пароль почтовой службы) не хранятся в репозитории: при разработке используются `dotnet user-secrets`, на сервере — переменные окружения.

## Порядок работы

- Основная ветка — `master`, прямые изменения в неё запрещены.
- Каждая задача выполняется в отдельной ветке.
- Изменения попадают в `master` только через Pull Request с одобрением второго участника команды.
- CI запускается при push в `master` и при Pull Request в `master`; сейчас он выполняет `restore` и `build`.
- Реальные данные клиентов в репозиторий не добавляются, в тестах используются только синтетические данные.

Подробности — в [`docs/development-process.md`](docs/development-process.md).
